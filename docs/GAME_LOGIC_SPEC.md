# Контракт движка и тесты

## Модули
- `game-core`: чистые функции `createRound(seed, players)`, `legalMoves(state, playerId)`, `applyMove(state, command)`, `resolveReachability(board)`, `isRoundOver(state)`.
- `server`: комнаты, случайность, авторитетное состояние, приватные представления, повторобезопасные команды и журнал событий.
- `web`: React/TypeScript интерфейс, адаптивное поле, рука, предпросмотр и подтверждение хода. Без SDK мессенджеров.
- `assets`: читать `data/asset-manifest.json` и `data/cards.json`, не угадывать пути.

## Команда
`{commandId, roomId, playerId, expectedRevision, type, cardId, target?, rotation?}`.
Сервер проверяет роль участника комнаты, чей ход, наличие карты в руке, действие и цель. При успехе атомарно повышает `revision` и публикует персонализированные события. Повтор того же `commandId` возвращает прежний результат без повторного эффекта.

## Информация
Публичное: игровое поле, открытые цели, имена, текущий ход, видимые неисправности, золото, публичный журнал. Приватное: роль, рука, порядок колоды, разведка. Никогда не передавать всем клиентам единый объект `state` и не скрывать секреты только CSS.

## Тестовая матрица
1. Нельзя строить без связи со стартом.
2. Все четыре края перекрёстка совпадают с соседями.
3. Два внешних порта «раздельного тупика» не дают прохода друг к другу.
4. Поворот 90° отклоняется.
5. Любая неисправность блокирует только строительство, не действия.
6. Парный ремонт удаляет ровно одну неисправность.
7. Обвал сохраняет отрезанные тайлы и отключает их от строительства.
8. Разведка раскрывает информацию только инициатору.
9. Золото завершает раунд независимо от роли последнего строителя.
10. Пустая цель не завершает раунд.
11. После исчерпания колоды ход продолжается, пока есть карты на руках.
12. Повтор `commandId` не меняет состояние дважды.
13. Повторное подключение не выдаёт чужие роли.
14. Два конкурентных хода с одной `revision` — только один принят.
15. Проверить 3 и 10 игроков, а также все три раунда.

## Важное для графики
В художественных WebP туннелей не должно быть текста и закрывающих порты рамок. Для геометрии использовать данные `connections`, а не пиксельный анализ. Текущие рисунки — прототипный экспорт, их стыковка визуально требует отдельной художественной QA.
