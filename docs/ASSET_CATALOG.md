# ASSET_CATALOG — план рабочего ассет-пака

Дата: 2026-11-08. Все позиции в этом документе пока имеют статус **planned**: это не отчёт о созданных изображениях. Реально поставляемые файлы перечисляются отдельно в data/asset-manifest.json.

Общие требования и размеры: [ASSET_SPEC.md](ASSET_SPEC.md). Художественное направление: [ART_DIRECTION.md](ART_DIRECTION.md).

## 1. Туннели

Папка: assets/cards/tunnels/. Все файлы: 512 × 768 WebP, без текста. N/E/S/W = верх/право/низ/лево. Разрешён только поворот на 180°; противоположные ориентации не требуют дубликатов. Ниже — рабочий список геометрий, а не утверждённое распределение экземпляров в колоде.

| Файл | Название в интерфейсе | Внутренние соединения |
| --- | --- | --- |
| tunnel-straight-ns.webp | Прямой проход | N соединён с S |
| tunnel-straight-ew.webp | Поперечный проход | E соединён с W |
| tunnel-turn-ne.webp | Поворот | N соединён с E |
| tunnel-turn-nw.webp | Поворот | N соединён с W |
| tunnel-tee-nes.webp | Развилка | N, E, S соединены |
| tunnel-tee-new.webp | Развилка | N, E, W соединены |
| tunnel-cross.webp | Перекрёсток | N, E, S, W соединены |
| tunnel-dead-end-n.webp | Тупик | Вход N заканчивается внутри |
| tunnel-dead-end-e.webp | Тупик | Вход E заканчивается внутри |
| tunnel-separated-n-s.webp | Раздельные тупики | N и S НЕ соединены |
| tunnel-separated-e-w.webp | Раздельные тупики | E и W НЕ соединены |

Любое дополнение к списку должно описывать компоненты связности до создания рисунка. Декоративная версия не добавляет новое правило. Не копировать точный художественный набор другого издателя.

Награды по номиналам не утверждают правила их раздачи: распределение и количество задаются последующей спецификацией логики.

## 7. Элементы, которые не нужно генерировать растровыми картинками

- Тексты, счёт, таймер, код комнаты, сообщения чата и описание выбранной карты.
- Сетка и координаты поля; подсветка разрешённых мест; предпросмотр и рамка выбора.
- Состояния кнопок; индикатор загрузки; предупреждение о переподключении.
- Простые пиктограммы назад, настройки, чат, звук, поворот, подтверждение, копирование, полноэкранный режим: SVG/CSS, единый стиль, достаточная зона касания.
- Статусы поломок: уменьшенный проверенный символ + понятная форма/маркер; не только цвет.

Шрифтовые файлы не включаются в этот пакет. Первоначально использовать системный стек; отдельный декоративный шрифт допускается только после проверки лицензии и явного решения о поставке.

## 8. Проверочные макеты экранов — не runtime-картинки

Отдельные экранные композиции нужны для: главного меню; входа/создания комнаты; лобби; приватной роли; поля и выбора карты; выбора цели действия; приватной разведки; итогов раунда; итогов матча; чата; правил/настроек; переподключения и ошибок.

Они используют реальные компоненты и ассеты. Макеты нельзя считать работающей игрой. Скриншоты в docs/previews/ допустимы для проверки, но приложение не должно строиться из скриншотов.

## 9. Порядок изготовления

1. Материалы и эталон: перекрёсток, прямая, поворот, тупик, одна поломка и один ремонт одинакового размера.
2. Проверочный стык нескольких туннелей, поворот на 180°, просмотр в руке и на поле.
3. Оставшиеся геометрии и карты действий.
4. Старт, цели, роли, награды и рубашки.
5. Фоны, аватары, бренд и интерфейсные детали.
6. Оптимизация, индивидуальные имена, реестр, измерения и техническая проверка всего набора.

Не производить десятки непроверенных вариаций до проверки первых стыков. Не объявлять этот каталог готовым ассет-паком.
