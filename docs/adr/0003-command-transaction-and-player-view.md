# ADR 0003. Атомарная команда и персональный снимок

Статус — принято для закрытой альфы по ТЗ 2.0.

## Контекст

Клиент может повторить команду после потери подтверждения. Одновременные команды должны дать согласованный результат, а повторное подключение должно вернуть состояние, доступное конкретному игроку.

## Решение

HTTP и WebSocket передают команды в одну службу. После проверки доступа PostgreSQL блокирует строку комнаты. Совпадение `commandId` и дайджеста возвращает прежний результат до проверки ожидаемой ревизии. Повторное использование ID с другим содержимым отклоняется. При принятии новой команды снимок, события, начисления и квитанция сохраняются в одной транзакции. Игровая ревизия увеличивается один раз за принятый переход движка.

Сервер строит `PlayerView` после проверки места. Проекция включает общую часть, собственную роль, руку, разведку, счёт и допустимые ходы. Роли и счёт раскрываются по правилам матча. Закрытое содержимое и состояние генератора случайности остаются на сервере. Клиент после разрыва получает полный персональный снимок. Бот получает ту же проекцию и допустимые ходы.

## Альтернативы и последствия

Проверка ревизии первой отклонила бы уже выполненную команду, чьё подтверждение потерялось. Раздельное сохранение снимка и квитанции создало бы окно для частичной записи. Передача полного состояния с фильтрацией в браузере раскрыла бы скрытые данные. Транзакция связывает результат команды с квитанцией, а серверная проекция задаёт границу доступа и общий формат восстановления для обоих транспортов.
